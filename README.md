# AdbController

WPF-приложение для управления Android-устройством через `adb` — графическая обёртка
над `adb shell`, `pm`, `dumpsys`, `input` и файловым доступом.

Собирается в **один .exe**, который работает на любом компьютере с Windows x64:
внутрь встроены .NET runtime и сам `adb.exe`, поэтому Android SDK устанавливать не нужно.

---

## Возможности

| Вкладка | Что делает |
|---|---|
| **Устройства** | Список подключённых устройств, переключение USB ⇄ TCP (`adb tcpip` / `connect` / `disconnect`). Последнее устройство запоминается и восстанавливается при следующем запуске. |
| **Инфо** | Модель, версия Android и ABI, батарея (уровень, температура, напряжение, мАч), CPU (загрузка + число ядер), RAM, диск, сетевой трафик со скоростью, uptime. Топ-5 процессов по CPU и RAM. Автообновление с настраиваемым интервалом. Сырые дампы `dumpsys` — в раскрывающихся блоках. |
| **APK** | Список пакетов (с системными или только 3rd party), пометка замороженных и подозрительных. Установка, удаление, заморозка (`pm disable-user`), разморозка, запуск, `dumpsys package`. Поиск рекламных модулей по списку ключевых слов с массовой заморозкой. |
| **Детектор** | Отслеживание активного приложения: узнаёт foreground-пакет через `dumpsys activity/window/recents` (несколько взаимоисключающих способов, запоминается рабочий). Лог переключений, счётчик появлений, пометка «горящих» пакетов, всплывающие уведомления. Кнопки заморозки / разморозки / удаления / инфо по выбранному пакету. Встроенная диагностика с сохранением сырых выводов на Рабочий стол. |
| **Массово (APK)** | Установка и удаление сразу нескольких APK / приложений с прогрессом и итоговым отчётом. |
| **Консоль ADB** | Произвольная команда `adb` с выводом в консоль. Раздел NTP: принудительная синхронизация времени, просмотр и смена NTP-сервера, автообновление по расписанию. |
| **Экран + Управление** | Живой скриншот устройства с масштабированием (слайдер, Ctrl+колесо, «вписать»), тап и свайп мышью прямо по скриншоту, ввод текста, кнопки Home / Back / Menu, автообновление кадра, сохранение PNG. |
| **Файлы (TC)** | Двухпанельный файловый менеджер: локальная папка ↔ папка на устройстве. Загрузка, выгрузка, удаление. |
| **Logcat** | Дамп журнала, очистка буфера, фильтр по тегу. |

Тёмная и светлая темы, все настройки (интервалы, масштаб, Wi-Fi IP/порт, папка с APK,
последнее устройство) сохраняются в `%APPDATA%\AdbController\settings.json`.

## Требования

- Windows x64 (только Windows — приложение на WPF).
- Установленный Android SDK **не требуется**: `adb.exe` встроен в сборку.
- Для работы по USB нужен драйвер Google USB Driver на телефоне.

## Сборка

```powershell
# Обычная сборка (framework-dependent)
dotnet build -c Release

# Готовый один .exe в dist\AdbController.exe
dotnet publish -c Release -o dist
```

Нужен **.NET 10 SDK**. Параметры публикации (single-file, self-contained, win-x64,
сжатие) уже зашиты в `AdbController.csproj`, поэтому достаточно `dotnet publish -c Release -o dist`.

### Встроенный adb

Бинарники `adb.exe` и его DLL лежат в `tools\platform-tools\` и встраиваются в сборку
как `EmbeddedResource`. При первом запуске они распаковываются в
`%LOCALAPPDATA%\AdbController\platform-tools\` и оттуда запускаются. Версия сверяется
по файлу `source.properties`, поэтому обновление распакованного adb происходит
автоматически после пересборки.

Если папки `tools\platform-tools\` нет (например, репозиторий склонирован без бинарников),
подготовь её скриптом:

```powershell
powershell -ExecutionPolicy Bypass -File tools\get-platform-tools.ps1
```

Скрипт копирует `adb.exe` и DLL из уже установленного platform-tools либо скачивает
официальный архив с `dl.google.com`.

Без встроенного adb приложение тоже собирается и запускается — оно найдёт системный
`adb.exe` в `PATH`, в `ANDROID_HOME` или в типовых местах установки.

### Как устроена работа с adb

Весь обмен с `adb.exe` идёт через `AdbRunner`:

- `adb.exe` ищется встроенным → рядом с программой → в переменных окружения SDK →
  в типовых путях → в `PATH`;
- `stdout` и `stderr` читаются **параллельно** — так исключается взаимоблокировка,
  когда переполняется буфер одного из каналов;
- таймаут **реально работает**: процесс принудительно завершается, а не висит;
- отсутствие `adb` — это не исключение, а результат `AdbResult.AdbNotFound`, поэтому
  приложение не падает и показывает понятное сообщение;
- все adb-вызовы выполняются вне UI-потока, интерфейс не подвисает.

## Известные ограничения

- Папки в файловом менеджере не копируются целиком — только файлы по одному.
- NTP-настройка игнорируется некоторыми прошивками (Realme/ColorOS, MIUI, OneUI) —
  это ограничение Android, в логе выводится предупреждение.
- Закладка `TAB` в консоли работает, но `adb shell` на некоторых прошивках требует
  ручной экранировки спецсимволов.
